## Rejected Experiments

Two bounded, model-only A/B experiments each make 24 real API requests:
two positives and four negatives, two trials, alternating order. They use the
same captured synthetic image and actual grounding questions. Non-original
counterfactual cases omit native-candidate evidence in both arms. They are not
desktop qualification or realistic release benchmarks.

The first adds a code-drawn ring to a second full-frame image while retaining
the original image unchanged. Green location changes from .88-.89 to .90;
authorization remains .89-.90. Gap rejection improves from .54-.55 to .07-.13.
Correct red location remains .67-.73. This does not fix positive grounding.

The second adds a full-resolution marked detail while retaining the original
full scene. Green location remains .87-.88 and authorization .85-.89. Red
location remains .67-.68. Gap uncertainty worsens to .55-.61. This is not a
reliability improvement and must not be shipped as one.

The marker's top-left coordinate mapping and the detail crop are checked by
real CoreGraphics output and visual inspection. Two initial review findings
were disproved: `request-*.json` does not match PNG files, and CoreGraphics
requires the Y conversion used by the tool. Source re-review returns PASS.
