## Production Shape

Do not loosen NativeReplacementProposal.make or create a D9 receipt
from an action that fails its current eligibility.

Add a distinct private loop-owned pending delivered-effect record:

1. Before a stamped nonvisual `set_value`, bind the actual request to
   exactly one nonsecure native field in the original document, exact
   source caller key/bytes, native owner/window, CF field, fact/index/role,
   finite frame and native ancestor roles. Do not infer semantic target.
   Initial matching value does not create a changed-value record.
2. Clear pending/observed delivery before every subsequent input.
   Retain the new pending record only after actual
   `outcome.dispatched && outcome.verified`. An outcome is not yet goal
   evidence. Failed, undispatched, denied, cancelled or unverified calls
   create nothing.
3. Promote it only against the NEXT ALREADY-SCHEDULED native observation,
   after that read proves the same task/source bytes/original document/
   CF field/fact/index/role/frame/hierarchy, complete context, unique
   nonsecure field and complete native value equal to the requested UTF-8
   bytes. No additional AX read is introduced. Any mismatch clears it,
   rather than rebinding it to the changed subject.
4. Expose factual `executed_replacement` in ordinary chooser state.
   This is not `_exact_replacement`: the latter still requires the
   unchanged D9 strong proposal and receipt.
5. On the .88 path there must be no replacement questions, no replacement
   votes and no exactReplacement proof. Any completion must pass the
   original GENERAL gates and fresh native readback. Strong D9 facts
   take precedence when a real D9 receipt is present.
6. Private CF identity and document fingerprint never enter JSON/logs.
   Nil/default observation slots preserve voice/control/read-only preview.
   No caller or extras can forge the loop-owned record.

Prefer a shared private native-field binding/check over copying identity
validation, but do not refactor unrelated code. The D9 factory must keep
the same public-to-this-module inputs and rejection behavior.
