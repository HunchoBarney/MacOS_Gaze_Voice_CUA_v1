How fast can a computer-use agent finish the job?

Most benchmarks only record whether an agent succeeded. cua-speedrun is an evaluation system that also measures how long each task takes and what its model calls cost. Every leaderboard run uses the same pipeline and virtual machine setup on Modal, a pay-per-second cloud service, and one agent interface works across OSWorld, OSWorld 2.0, CUA-World, and MyPCBench. Smaller task sets, chosen so model rankings match the full benchmarks, keep repeated runs affordable.

Same machine, same clock, any agent

cua-speedrun is the software that runs these comparisons. It holds the hardware, desktops, tasks, and timing fixed, so differences in time and cost come from the agent.

 What each task's time includes. Agent time and environment time are recorded separately inside the timed interval.

Identical hardware for every runAgents and desktops run in separate Modal sandboxes, built from the same pinned images for every run. Open-weight models are served with vLLM on fixed L40S GPUs. Results do not depend on whose computer launched the run.

One agent, four benchmarksAn agent is a folder with an agent.py that receives 1920×1080 screenshots and sends keyboard and mouse actions, and an init.py that sets it up. The same folder runs on OSWorld, OSWorld 2.0, CUA-World, and MyPCBench.

A clock that measures the agentSetup and scoring happen off the clock. If a desktop or sandbox fails, the task is retried. If the agent crashes, the task counts as failed. Each agent reports its model cost after every request.

Inputs that do what they sayOur test tool, CUA-AutoDebug, sends 94 keyboard and mouse inputs to an app that records what arrives. PyAutoGUI over SSH, a common setup, got 11 wrong, such as typing > when < was requested. Our runtime got all 94 right, five times each.

Smaller task sets that keep the rankingWe chose 50 of 295 OSWorld tasks so that model rankings match the full benchmark. On models not used to choose them, the rank correlation is 0.98.

An optional Fast I/O modeFast I/O mode (FastCUA) cuts the delay between an action and the next screenshot from about 2–3 s to 2–28 ms, to test whether agents benefit from a faster desktop. Leaderboard results use the normal mode unless marked Fast I/O.

Results we did not expect

A faster environment, a slower agent. With Fast I/O on, GPT-6 Astra at low effort took 99.0 s per task instead of 89.5 s, averaged over five runs. Screenshots arrived before applications finished updating, so the agent looked again or repeated itself.

Evaluate your own agent

Start with an included agent or bring your own Python implementation. The toolkit prepares the desktops, runs benchmark tasks, and saves scores, timings, screenshots, and action logs. It supports OSWorld, OSWorld 2.0, CUA-World, and MyPCBench.

To start right away, open the notebook on Modal, fork it, and run its one cell. Or use the command line:

Copypip install cua-speedrun
cua-speedrun setup
cua-speedrun benchmark

setup saves your Modal credentials and API keys. benchmark asks for an agent and a task set, then shows progress. Compute uses your Modal account and model calls use your API key.
