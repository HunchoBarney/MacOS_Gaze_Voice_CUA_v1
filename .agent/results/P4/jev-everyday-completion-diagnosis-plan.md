# Everyday Completion Diagnosis

The signed native-target candidate calculates 3 + 4 and independently reads back
7, then reports blocked. Its scalar native-observation logs show complete reads,
with no depth, action, role or time-bound failures. Missing native completeness
is therefore rejected as the explanation. Neither frozen-image experiment
passed all existing thresholds; neither is a production change.

Capture one read-only production-preview decision over that same Calculator
window and its already-achieved goal. Record actual state, questions and model
answers before deciding whether code, evidence or model judgment is responsible.
This is diagnosis, not signed-app, reliability, physical Fn or release proof.

## Scope And Failure Modes

- Only the exact Calculator window in the independently verified signed pilot
  receipt is eligible. Reject another bundle, process, window or display value.
- Never launch an app, send input or replay the calculation. The replay seam
  accepts only list_apps, list_windows and get_window_state; every other call
  throws. The signed daemon is used only for the fresh scoped snapshot.
- Recheck the independent native display before and after preview. Refuse to
  interpret a changed display as the original failure.
- Retain the full original scoped image, native evidence and actual questions.
  Do not add an expected result to the model's goal or state.
- Keep output owner-private and exclusive. Credentials enter only the existing
  test client's environment and never the saved requests or command line.
- One controlled capture, 120-second replay deadline. Run through the serialized
  verification lane and desktop lock. No production source or threshold change.
