<header class="release-heading">
  <h1>cua-<strong>speedrun</strong><span class="title-caret" aria-hidden="true"></span></h1>
  <p class="release-purpose">How fast can a computer-use agent finish the job?</p>
  <p class="release-description">Most benchmarks only record whether an agent succeeded. cua-speedrun is an evaluation system that also measures how long each task takes and what its model calls cost. Every leaderboard run uses the same pipeline and virtual machine setup on Modal, a pay-per-second cloud service, and one agent interface works across OSWorld, OSWorld 2.0, CUA-World, and MyPCBench. Smaller task sets, chosen so model rankings match the full benchmarks, keep repeated runs affordable.</p>

<section class="infra" aria-labelledby="infra-heading" data-reveal>
  <h2 id="infra-heading">Same machine, same clock, any agent</h2>
  <p class="infra-lede">cua-speedrun is the software that runs these comparisons. It holds the hardware, desktops, tasks, and timing fixed, so differences in time and cost come from the agent.</p>
  <figure class="clock-line" aria-labelledby="clock-line-caption">
  <ol class="clock-steps">
    <li class="is-off"><span class="clock-tag">Off the clock</span><p>Start the agent and desktop sandboxes, reset the desktop for the task, run the agent's setup (<code>init.py</code>)</p></li>
    <li class="is-on"><span class="clock-tag">On the clock</span><p><span class="clock-flag">Starts when the instruction is sent</span>Screenshot, model call, keyboard and mouse actions, repeated<span class="clock-flag is-stop">Stops at done or the time limit</span></p><span class="clock-ticks" aria-hidden="true"></span></li>
    <li class="is-off"><span class="clock-tag">Off the clock</span><p>The benchmark's verifier scores the final state and trajectory</p></li>
  </ol>
  <figcaption id="clock-line-caption">What each task's time includes. Agent time and environment time are recorded separately inside the timed interval.</figcaption>
</figure>
  <dl class="infra-list">
    <div><dt>Identical hardware for every run</dt><dd>Agents and desktops run in separate Modal sandboxes, built from the same pinned images for every run. Open-weight models are served with vLLM on fixed L40S GPUs. Results do not depend on whose computer launched the run.</dd></div>
    <div><dt>One agent, four benchmarks</dt><dd>An agent is a folder with an <code>agent.py</code> that receives 1920×1080 screenshots and sends keyboard and mouse actions, and an <code>init.py</code> that sets it up. The same folder runs on OSWorld, OSWorld 2.0, CUA-World, and MyPCBench.</dd></div>
    <div><dt>A clock that measures the agent</dt><dd>Setup and scoring happen off the clock. If a desktop or sandbox fails, the task is retried. If the agent crashes, the task counts as failed. Each agent reports its model cost after every request.</dd></div>
    <div><dt>Inputs that do what they say</dt><dd>Our test tool, CUA-AutoDebug, sends 94 keyboard and mouse inputs to an app that records what arrives. PyAutoGUI over SSH, a common setup, got 11 wrong, such as typing &gt; when &lt; was requested. Our runtime got all 94 right, five times each.</dd></div>
    <div><dt>Smaller task sets that keep the ranking</dt><dd>We chose 50 of 295 OSWorld tasks so that model rankings match the full benchmark. On models not used to choose them, the rank correlation is 0.98.</dd></div>
    <div><dt>An optional Fast I/O mode</dt><dd>Fast I/O mode (FastCUA) cuts the delay between an action and the next screenshot from about 2–3 s to 2–28 ms, to test whether agents benefit from a faster desktop. Leaderboard results use the normal mode unless marked Fast I/O.</dd></div>
  </dl>
  <p class="infra-more"><a href="https://arxiv.org/abs/2609.40284">Read the paper</a> · <a href="/docs.html">Run it yourself</a></p>
</section>
<section class="splits" aria-labelledby="splits-heading" data-reveal>
  <h2 id="splits-heading">Results we did not expect</h2>
  <ol class="split-list">
    <li class="split is-behind">
      <p class="split-what"><strong>A faster environment, a slower agent.</strong> With Fast I/O on, GPT-6 Astra at low effort took 99.0 s per task instead of 89.5 s, averaged over five runs. Screenshots arrived before applications finished updating, so the agent looked again or repeated itself.</p>
      <p class="split-times"><span>89.5 s</span><span>99.0 s</span></p>
      <p class="split-delta">+9.5 s</p>
    </li>
    <li class="split is-behind">
      <p class="split-what"><strong>Same score, four times the wait.</strong> Kimi K3, an open-weight model, at max effort matches GPT-6 Astra at high effort on OSWorld (89.6%). For every open-weight model we tested, another model scored at least as high in less time, and another scored at least as high for less money.</p>
      <p class="split-times"><span>101 s</span><span>444 s</span></p>
      <p class="split-delta">×4.4</p>
    </li>
    <li class="split is-gold">
      <p class="split-what"><strong>Fewer tasks, similar ranking.</strong> A 50-task OSWorld subset, chosen so that historical scores match the full set, cuts evaluation time by 84.9%.</p>
      <p class="split-times"><span>295 tasks</span><span>50 tasks</span></p>
      <p class="split-delta">−84.9%</p>
    </li>
    <li class="split is-ahead">
      <p class="split-what"><strong>More reasoning, less time.</strong> Gemini 3 Flash Preview on OSWorld, low to medium reasoning effort. The score also rose from 33.6% to 57.6%; extra thinking replaced repeated failed actions.</p>
      <p class="split-times"><span>492 s</span><span>268 s</span></p>
      <p class="split-delta">−224 s</p>
    </li>
  </ol>

  <section aria-labelledby="software-heading" data-reveal>
    <h2 id="software-heading">Evaluate your own agent</h2>
    <p>Start with an included agent or bring your own Python implementation. The toolkit prepares the desktops, runs benchmark tasks, and saves scores, timings, screenshots, and action logs. It supports OSWorld, OSWorld 2.0, CUA-World, and MyPCBench.</p>
    <p>To start right away, <a href="https://modal.com/notebooks/cuaspeedrun/main/nb-HChvIDifDakkiExD84Ir8B" target="_blank" rel="noopener">open the notebook on Modal</a>, fork it, and run its one cell. Or use the command line:</p>
    <div class="code-block"><button type="button" data-copy>Copy</button><pre><code>pip install cua-speedrun
cua-speedrun setup
cua-speedrun benchmark</code></pre></div>
    <p class="code-caption"><code>setup</code> saves your Modal credentials and API keys. <code>benchmark</code> asks for an agent and a task set, then shows progress. Compute uses your Modal account and model calls use your API key.</p>
    <p>See how to <a href="/docs.html#own-agent">add your own agent</a>, <a href="/docs.html#open-weights">serve an open-weight model</a>, or <a href="/docs.html#add-benchmark">add a benchmark</a>.</p>
